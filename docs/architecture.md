# Архитектура Data Ingestion Pipeline

## Обзор системы

Data Ingestion Pipeline представляет собой ETL-систему для извлечения данных о розничных магазинах из Google Places API, их обогащения через динамические JavaScript шаблоны и сохранения в ClickHouse с использованием Data Vault архитектуры.

## Компоненты

### 1. Конфигурационный слой (`src/config.py`)

**Ответственность:**
- Загрузка настроек из переменных окружения
- Валидация конфигурации через Pydantic
- Предоставление единой точки доступа к настройкам

**Паттерны:**
- Singleton для глобального экземпляра настроек
- Settings classes для группировки связанных параметров

**Группы настроек:**
- `DatabaseSettings` - настройки ClickHouse (использует префикс `POSTGRES_` для совместимости)
- `GooglePlacesSettings` - настройки Google Places API
- `SearchSettings` - параметры поиска
- `BrowserSettings` - настройки браузера для веб-скрапинга
- `PipelineSettings` - настройки параллелизма и логирования

### 2. Слой данных (`src/database/clickhouse/`)

**Ответственность:**
- Определение Data Vault схемы
- Управление подключениями к ClickHouse
- Абстракция работы с ClickHouse Data Vault

**Паттерны:**
- Repository pattern через ClickHouse клиент
- Data Vault архитектура (Hub-Satellite-Link)
- Factory pattern для создания подключений

**Data Vault модель:**

#### Hub таблицы (бизнес-ключи)
- `hub_stores` - уникальные магазины (по place_id)
- `hub_fields` - метаданные динамических полей
- `hub_attributes` - метаданные атрибутов

#### Satellite таблицы (исторические данные)
- `sat_store_attributes` - атрибуты магазинов (name, address, phone, website, координаты, рейтинг, extracted_fields)
- `sat_field_values` - значения динамических полей
- `sat_store_raw` - сырые данные из API

#### Link таблицы (связи)
- `link_store_fields` - связи магазин-поле

#### Представления
- `vw_store_data` - удобное чтение данных (последняя версия)
- `mv_store_search` - материализованное представление для поиска
- `mv_field_stats` - статистика по полям

### 3. Слой интеграции с внешними API (`src/api/`)

**Ответственность:**
- Взаимодействие с Google Places API
- Обработка пагинации результатов
- Нормализация данных из API

**Паттерны:**
- Adapter pattern для абстракции API
- Strategy pattern для различных типов запросов
- Error handling с graceful degradation

**Основные компоненты:**
- `client.py` - асинхронный клиент Google Places API
- `search.py` - функции поиска мест
- `normalizer.py` - нормализация данных для БД
- `factory.py` - фабричные функции

**Основные методы:**
- `search_places()` - текстовый поиск мест
- `get_place_details()` - получение детальной информации
- `normalize_place_data()` - нормализация для БД

### 4. Слой обогащения данных (`src/extraction/`)

**Ответственность:**
- Извлечение данных с веб-сайтов через динамические JavaScript шаблоны
- Обход защиты от ботов через pyppeteer
- Асинхронная обработка запросов

**Паттерны:**
- Async/Await для неблокирующих операций
- Template pattern для динамических шаблонов
- Stealth techniques для обхода защиты
- Fallback strategies при ошибках

**Компоненты:**
- `browser.py` - управление браузером (pyppeteer)
- `extractor.py` - применение JavaScript шаблонов
- `templates.py` - загрузка и управление шаблонами
- `templates/*.js` - JavaScript шаблоны для извлечения данных

**Динамические шаблоны:**
- Автоматическая загрузка из `src/extraction/templates/`
- Порядок выполнения по нумерации файлов (01_, 02_, etc.)
- Расширяемость - добавление новых полей без изменения кода

**Алгоритм извлечения:**
1. Загрузка страницы через pyppeteer
2. Применение stealth режима
3. Выполнение всех JavaScript шаблонов по порядку
4. Сбор результатов в словарь extracted_fields
5. Обработка таймаутов и ошибок

### 5. Слой оркестрации (`src/pipeline/`)

**Ответственность:**
- Координация всех компонентов
- Управление потоком данных
- Обработка ошибок и логирование

**Паттерны:**
- Pipeline pattern для последовательной обработки
- Template method для стандартизации процесса
- Observer pattern через логирование

**Компоненты:**
- `orchestrator.py` - координация этапов pipeline
- `base.py` - базовые классы ETLStep и PipelineContext
- `fetcher.py` - извлечение данных из Google Places API
- `enricher.py` - обогащение данных через веб-скрапинг

**Поток данных:**
```
1. Инициализация ClickHouse и браузера (параллельно)
   ↓
2. Поиск мест через Google Places API (DataFetcher)
   ↓
3. Нормализация данных
   ↓
4. Обогащение через веб-сайты (DataEnricher, опционально)
   ↓
5. Сохранение/обновление в ClickHouse Data Vault (ClickHouseDataSaver)
   ↓
6. Логирование результатов
```

## Обработка ошибок

### Стратегии обработки:

1. **API ошибки:**
   - Retry с экспоненциальной задержкой
   - Graceful degradation (продолжение без обогащения)
   - Детальное логирование

2. **Ошибки БД:**
   - Изоляция ошибок на уровне записи
   - Продолжение обработки остальных записей
   - Логирование в таблицу processing_errors

3. **Ошибки обогащения:**
   - Таймауты для долгих операций
   - Пропуск недоступных сайтов
   - Сохранение базовых данных без обогащения

## Развертывание

### Docker Compose архитектура:

```
┌─────────────────┐
│   ClickHouse    │
│   Container     │
└────────┬────────┘
         │
         │ Network
         │
┌────────▼────────┐
│  Python App     │
│  Container      │
│  - Places API   │
│  - Enrichment   │
│  - Pipeline     │
└─────────────────┘
         │
         │ (optional)
         │
┌────────▼────────┐
│   Jupyter       │
│   Container     │
│   - Analytics   │
└─────────────────┘
```

### Переменные окружения:

- `POSTGRES_*` - настройки ClickHouse (для совместимости используется префикс POSTGRES_)
- `GOOGLE_PLACES_*` - настройки Google Places API
- `SEARCH_*` - параметры поиска
- `BROWSER_*` - настройки браузера
